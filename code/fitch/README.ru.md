# fitch

Программа проверки доказательств в натуральной дедукции в стиле Фитча для пропозициональной логики.

Доказательство — это плоский список из `Step`.
Каждый шаг несёт формулу, глубину вложенности (0 = основное доказательство, 1 = внутри одного поддоказательства, ...) и обоснование: допущение или правило, применённое к более ранним строкам.
Программа проверки проверяет, что каждое умозаключение является корректным применением своего правила и что каждая цитируемая строка всё ещё находится в области видимости — строку внутри закрытого поддоказательства больше нельзя использовать.

## Быстрый старт

```bash
cargo run --example contrapositive
cargo run --example rejected
cargo test
```

## Идея

Натуральная дедукция формализует математическое доказательство как игру правил введения и исключения.
Чтобы доказать `A -> B`, допустите `A` в поддоказательстве и выведите `B`.
Чтобы использовать `A -> B`, соедините его с `A` и заключите `B`:

$$\frac{[A] \;\; B}{A \to B} \;(\to\text{I}) \qquad\qquad \frac{A \to B \qquad A}{B} \;(\to\text{E})$$

Квадратные скобки отмечают допущение, закрываемое правилом введения.
Диаграммы Фитча изображают такие поддоказательства вложенными рамками, и здесь вложенность — это поле `depth`.
Набор правил полон для классической пропозициональной логики: исключение двойного отрицания (`Dne`) — единственный классический шаг, все остальные правила интуиционистски общезначимы.

## Демо

| Демо             | Что показывает                                                                                        |
| ---------------- | ----------------------------------------------------------------------------------------------------- |
| `contrapositive` | Строит и проверяет доказательство `(P -> Q) -> (~Q -> ~P)` с двумя вложенными поддоказательствами     |
| `rejected`       | Два некорректных доказательства — неверный дизъюнкт и строка вне области видимости — и ошибка каждого |

## API

| Элемент                                         | Что делает                                                                 |
| ----------------------------------------------- | -------------------------------------------------------------------------- |
| `Formula`                                       | Пропозициональная формула: `Atom`, `Bottom`, `Not`, `And`, `Or`, `Implies` |
| `atom`, `bottom`, `not`, `and`, `or`, `implies` | Конструкторы формул                                                        |
| `Step { depth, formula, just }`                 | Одна строка доказательства                                                 |
| `Just`                                          | Обоснование шага, один вариант на правило (таблица ниже)                   |
| `check(&[Step]) -> Result<(), Error>`           | Проверяет каждый шаг, `Error` называет нарушающую строку и причину         |

### Правила

| Обоснование                      | Посылки                                                       | Заключение     |
| -------------------------------- | ------------------------------------------------------------- | -------------- |
| `Assumption`                     | —                                                             | само допущение |
| `AndIntro { left, right }`       | `A`, `B`                                                      | `A ∧ B`        |
| `AndElimLeft { conj }`           | `A ∧ B`                                                       | `A`            |
| `AndElimRight { conj }`          | `A ∧ B`                                                       | `B`            |
| `OrIntroLeft { disj }`           | `A`                                                           | `A ∨ B`        |
| `OrIntroRight { disj }`          | `B`                                                           | `A ∨ B`        |
| `OrElim { disj, left, right }`   | `A ∨ B`, поддоказательство `A ⊢ C`, поддоказательство `B ⊢ C` | `C`            |
| `ImpliesIntro { assump, concl }` | поддоказательство `A ⊢ B`                                     | `A -> B`       |
| `ImpliesElim { imp, ante }`      | `A -> B`, `A`                                                 | `B`            |
| `NotIntro { assump, concl }`     | поддоказательство `A ⊢ ⊥`                                     | `¬A`           |
| `NotElim { neg, pos }`           | `¬A`, `A`                                                     | `⊥`            |
| `BotElim { bot }`                | `⊥`                                                           | `A`            |
| `Dne { notnot }`                 | `¬¬A`                                                         | `A` (классика) |

Поддоказательство цитируется первой строкой-допущением и последней строкой, и правило закрывает их оба.

Формулы строятся конструкторами и выводятся в обычной записи:

```rust
use fitch::{atom, implies, not};

let p = atom("P");
let q = atom("Q");
let contra = implies(implies(p.clone(), q.clone()), implies(not(q), not(p)));
assert_eq!(contra.to_string(), "((P -> Q) -> (¬Q -> ¬P))");
```

Доказательства проверяются строка за строкой:

```rust
use fitch::{atom, check, or, Just, Step};

// P ⊢ P ∨ Q by ∨-introduction.
let steps = vec![
    Step { depth: 0, formula: atom("P"), just: Just::Assumption },
    Step { depth: 0, formula: or(atom("P"), atom("Q")), just: Just::OrIntroLeft { disj: 1 } },
];
assert!(check(&steps).is_ok());
```

## Тесты

Модульные тесты покрывают вывод контрапозиции, исключение двойного отрицания и исключение дизъюнкции с двумя случаями.
Тесты на отказ фиксируют ошибку для неверного дизъюнкта, строки вне области видимости и правила, выводящего формулу, отличную от заявленной.
