# prolog

Термы, подстановки, унификация и база дизъюнктов.

Намеренно небольшая модель *данных* логического программирования.
Библиотека заканчивается там, где теория термов и унификации полна.

## Быстрый старт

```bash
cargo run --example family_tree
cargo run --example unify_demo
cargo test
```

## Идея

Логическая программа — это множество определённых дизъюнктов.
Факт `parent(alice, bob).` утверждает, что предикат выполняется.
Правило `ancestor(X, Y) :- parent(X, Y).` говорит, что голова выполняется всякий раз, когда выполняется тело.
Этот крейт моделирует ингредиенты такой программы, и ничего больше:

- `Term` — переменные, константы и структуры, со списками как синтаксическим сахаром над функторами `.`/`[]`.
- `Subst` и `unify` — решение уравнений между термами с проверкой вхождения (occurs check): переменная никогда не связывается с термом, который её содержит.
- `Clause`, `Goal`, `Database` — факты, правила и программа, индексированная по предикату.

Центральная операция — унификация: подстановка $\sigma$ унифицирует $t_1$ и $t_2$, если

$$\sigma t_1 = \sigma t_2,$$

а `unify` расширяет $\sigma$ до наиболее общей такой подстановки.

Чего *нет* — это движка, который запускает запрос: SLD-решателя с поиском в глубину и возвратом.
Он сопоставляет цель с головами дизъюнктов через унификацию, держит по одной приостановленной деривации на каждый подходящий дизъюнкт и откатывается, когда ветвь гибнет.
Построение такого решателя поверх этих кусочков — самостоятельное упражнение.

## API

| Элемент                                    | Модуль     | Назначение                                                  |
| ------------------------------------------ | ---------- | ----------------------------------------------------------- |
| `Term::var`, `Term::atom`, `Term::struct_` | `term`     | Построение термов                                           |
| `Term::nil`, `Term::cons`, `Term::list`    | `term`     | Построение списков                                          |
| `Term::vars`, `Term::contains`             | `term`     | Интроспекция переменных и проверка вхождения (occurs check) |
| `Subst`                                    | `subst`    | Подстановка: `HashMap<usize, Term>`                         |
| `apply`, `apply_goal`                      | `subst`    | Применение подстановки к терму или цели                     |
| `unify`, `UnifyError`                      | `unify`    | Унификация двух термов, расширяющая подстановку             |
| `Goal::true_`, `Goal::call`, `Goal::conj`  | `goal`     | Построение целей                                            |
| `Clause::fact`, `Clause::rule`             | `clause`   | Построение фактов и правил                                  |
| `Database::add`, `Database::clauses_for`   | `database` | Программа, индексированная по предикату                     |

## Демо

| Демо          | Показывает                                                                                        |
| ------------- | ------------------------------------------------------------------------------------------------- |
| `family_tree` | Базу дизъюнктов из фактов `parent` и рекурсивных правил `ancestor`, плюс унификацию цели с фактом |
| `unify_demo`  | Три уравнения, решаемые по шагам, и проверку вхождения, отвергающую `X = f(X)`                    |

Демо `family_tree` строит классическую программу про родителей и предков и сопоставляет `parent(_0, _1)` с фактом `parent(alice, bob)`.
Демо `unify_demo` печатает наиболее общий унификатор и общий экземпляр для двух разрешимых уравнений.

## Тесты

Юнит-тесты лежат рядом с каждым модулем.
Каждый публичный элемент несёт doctest.

## Вне рамок

Ядро не имеет парсера, REPL, арифметики, отсечения или отрицания и не имеет SLD-решателя.
Естественные продолжения над этим ядром — парсер синтаксиса `term.` / `?- term.`, арифметический `is`, отсечение с его барьером и SLD-решатель с возвратом.
