# prolog

Миниатюрный Prolog: термы, унификация и SLD-резолюция.

Намеренно небольшая модель ядра Prolog как математической системы.
Без парсера, без REPL, без арифметики, без отсечения --- язык заканчивается там, где теория полна и начинается студенческий проект.

## Быстрый старт

```bash
cargo run -p prolog --example family_tree
cargo run -p prolog --example reachability
cargo run -p prolog --example unify_demo
cargo run -p prolog --example sld_trace
cargo test -p prolog
```

## Идея

Логическая программа --- это множество определённых дизъюнктов.
Факт `parent(alice, bob).` утверждает, что предикат выполняется; правило `ancestor(X, Y) :- parent(X, Y).` говорит, что голова выполняется всякий раз, когда выполняется тело.
Запрос `?- ancestor(alice, Y).` спрашивает, какие подстановки вместо `Y` делают цель логическим следствием программы.

Решатель отвечает посредством SLD-резолюции: он выбирает самую левую цель, сопоставляет её с дизъюнктами программы по порядку с помощью унификации и помещает в стек одну приостановленную деривацию на каждый подходящий дизъюнкт.
Поиск в глубину со стеком точек выбора, с возвратом при гибели ветви --- это и есть бэктрекинг.

Крейт моделирует каждый ингредиент отдельно:

- `Term` --- переменные, константы и структуры, со списками как синтаксическим сахаром над функторами `.`/`[]`;
- `Subst` и `unify` --- решение уравнений между термами, с проверкой вхождения (occurs check) (переменная никогда не связывается с термом, который её содержит);
- `Clause`, `Goal`, `Database` --- факты, правила и программа;
- `Solver` --- SLD-поиск, по одному решению за вызов `next_solution`, плюс ограниченный вариант для изучения незавершения и трасса для наблюдения за поиском.

Дерево поиска для `ancestor(alice, Y)` при базовом правиле первым:

```text
?- ancestor(alice, Y).
    ancestor(alice, Y)
    +-- ancestor(alice, Y) :- parent(alice, Y).        -> parent(alice, Y) -> Y = bob
    +-- ancestor(alice, Y) :- parent(alice, Z), ancestor(Z, Y).
        +-- parent(alice, Z) -> Z = bob, ancestor(bob, Y)
            +-- ... (base rule)                        -> Y = carol
            +-- ... (recursive rule)                   -> Y = dave
```

## API

| Элемент | Модуль | Назначение |
| --- | --- | --- |
| `Term::var`, `Term::atom`, `Term::struct_` | `term` | Построение термов |
| `Term::nil`, `Term::cons`, `Term::list` | `term` | Построение списков |
| `Term::vars`, `Term::contains` | `term` | Интроспекция переменных, проверка вхождения (occurs check) |
| `Subst` | `subst` | Подстановка: `HashMap<usize, Term>` |
| `apply`, `apply_goal` | `subst` | Применение подстановки к терму / цели |
| `unify`, `UnifyError` | `unify` | Унификация двух термов, расширяющая подстановку |
| `Goal::true_`, `Goal::call`, `Goal::conj` | `goal` | Построение целей |
| `Clause::fact`, `Clause::rule` | `clause` | Построение фактов и правил |
| `Query::new`, `Query::answer` | `query` | Цель с именованными переменными ответа |
| `Database::add`, `clauses_for` | `database` | Программа, индексированная по предикату |
| `rename_clause` | `rename` | Стандартизировать дизъюнкт отдельно (переименовать переменные) |
| `Solver::solve` | `solver` | Собрать до N решений |
| `Solver::solve_bounded` | `solver` | Решать в рамках бюджета шагов |
| `Solver::solve_traced`, `TraceEvent` | `solver` | Решать и записывать поиск |

## Демо

| Демо | Показывает |
| --- | --- |
| `family_tree` | Факты и рекурсивные правила над `parent`/`ancestor`; ответы в порядке программы |
| `reachability` | Достижимость в графе как рекурсивные правила; правая рекурсивная форма, завершающаяся на ациклических графах |
| `unify_demo` | Наиболее общие унификаторы вручную; проверка вхождения, отвергающая `X = f(X)` |
| `sld_trace` | SLD-поиск как стенограмма: вызовы, выбор дизъюнктов, возвраты (бэктрекинг) |

## Тесты

Юнит-тесты лежат рядом с каждым модулем; `tests/scenarios.rs` запускает целые программы от начала до конца (append, склеивающий и разбивающий список, reverse).
Каждый публичный элемент несёт doctest.

## Вне рамок

Ядро не имеет парсера, REPL, арифметики и отсечения или отрицания.
Построение парсера для синтаксиса `term.` / `?- term.`, арифметического `is` или отсечения с его барьером отсечения поверх `Solver` --- это студенческий проект.
