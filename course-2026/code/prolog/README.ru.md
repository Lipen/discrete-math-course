# prolog

Термы, подстановки, унификация и база дизъюнктов.

Намеренно небольшая модель *данных* Prolog как математической системы.
Без парсера, без REPL, без арифметики, без отсечения, без решателя --- библиотека заканчивается там, где теория термов и унификации полна, и начинается студенческий проект.

## Быстрый старт

```bash
cargo run -p prolog --example family_tree
cargo run -p prolog --example unify_demo
cargo test -p prolog
```

## Идея

Логическая программа --- это множество определённых дизъюнктов.
Факт `parent(alice, bob).` утверждает, что предикат выполняется; правило `ancestor(X, Y) :- parent(X, Y).` говорит, что голова выполняется всякий раз, когда выполняется тело.
Этот крейт моделирует ингредиенты такой программы, и ничего больше:

- `Term` --- переменные, константы и структуры, со списками как синтаксическим сахаром над функторами `.`/`[]`;
- `Subst` и `unify` --- решение уравнений между термами, с проверкой вхождения (occurs check) (переменная никогда не связывается с термом, который её содержит);
- `Clause`, `Goal`, `Database` --- факты, правила и программа, индексированная по предикату.

Чего *нет* --- это движка, который запускает запрос: SLD-решателя с поиском в глубину и возвратом.
Он сопоставляет цель с головами дизъюнктов через унификацию, помещает в стек по одной приостановленной деривации на каждый подходящий дизъюнкт и откатывается, когда ветвь гибнет.
Построение такого решателя поверх этих кусочков --- это студенческий проект.

## API

| Элемент | Модуль | Назначение |
| --- | --- | --- |
| `Term::var`, `Term::atom`, `Term::struct_` | `term` | Построение термов |
| `Term::nil`, `Term::cons`, `Term::list` | `term` | Построение списков |
| `Term::vars`, `Term::contains` | `term` | Интроспекция переменных, проверка вхождения (occurs check) |
| `Subst` | `subst` | Подстановка: `HashMap<usize, Term>` |
| `apply`, `apply_goal` | `subst` | Применение подстановки к терму / цели |
| `unify`, `UnifyError` | `unify` | Унификация двух термов, расширяющая подстановку |
| `Goal::true_`, `Goal::call`, `Goal::conj` | `goal` | Построение целей |
| `Clause::fact`, `Clause::rule` | `clause` | Построение фактов и правил |
| `Database::add`, `clauses_for` | `database` | Программа, индексированная по предикату |

## Демо

| Демо | Показывает |
| --- | --- |
| `family_tree` | Факты и рекурсивные правила над `parent`/`ancestor`, плюс унификация цели с фактом |
| `unify_demo` | Наиболее общие унификаторы вручную; проверка вхождения, отвергающая `X = f(X)` |

## Тесты

Юнит-тесты лежат рядом с каждым модулем.
Каждый публичный элемент несёт doctest.

## Вне рамок

Ядро не имеет парсера, REPL, арифметики, отсечения или отрицания и не имеет SLD-решателя.
Построение парсера для синтаксиса `term.` / `?- term.`, арифметического `is`, отсечения с его барьером отсечения и SLD-решателя с возвратом поверх этого ядра --- это студенческий проект.
