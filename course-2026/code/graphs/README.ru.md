# graphs

Графы: моделирование, алгоритмы, визуализация.

Намеренно простая модель графа — идентификаторы вершин `usize`, необязательные имена, взвешенные рёбра, без дженериков и типажей — плюс классические алгоритмы и несколько способов отобразить граф.

## Быстрый старт

```bash
cargo run --example bfs_dfs
cargo run --example visualize
cargo test
```

## Модель

`Graph` хранит свои данные дважды, и оба представления открыты.
`edges` — список рёбер `(from, to, weight)`, который читают взвешенные алгоритмы (Дейкстра, Беллман–Форд, Краскал).
`adj` — списки смежности `adj[u] = [(neighbor, edge_id), ...]`, которые читают обходы (BFS, DFS).

Вершины — идентификаторы `usize` из `0..n` с необязательными строковыми именами.
Флаг `directed` выбирает стрелки или обычные линии.
Рёбра могут повторяться, поэтому мультиграфы разрешены.
Дублирование намеренно: именно так псевдокод мыслит граф, и каждый алгоритм остаётся коротким.

Второе представление живёт в `matrix.rs`: `AdjMatrix`, таблица весов рёбер размером $n \times n$.
Оно подходит для плотных графов, проверок рёбер за $O(1)$ и матричных методов вроде подсчёта путей через степени матрицы.
Преобразования работают в обе стороны (`AdjMatrix::from_graph`, `AdjMatrix::to_graph`).
Матрица не может хранить параллельные рёбра, поэтому преобразование схлопывает их в самое лёгкое.

![Взвешенный граф, размещённый graphviz (движок `dot`) по DOT-выводу крейта](assets/graphs-demo.svg)

На рисунке граф демо `visualize`: крейт записывает исходник DOT, а пример рисует картинку командой `dot -O -Tsvg`.
Исходник DOT лежит в [`assets/graphs-demo.dot`](assets/graphs-demo.dot), разметку можно перестроить любым движком Graphviz (`dot`, `neato`, `fdp`, `circo`).

## Демо

| Демо               | Показывает                                                                                                         |
| ------------------ | ------------------------------------------------------------------------------------------------------------------ |
| `bfs_dfs`          | слои и расстояния BFS, времена входа/выхода DFS на сквозном примере графа                                          |
| `dijkstra`         | Дейкстра против Беллмана–Форда, отрицательные рёбра и отрицательные циклы, восстановление пути                     |
| `mst`              | минимальное остовное дерево Краскала на взвешенном графе                                                           |
| `structure`        | компоненты, мосты, точки сочленения, двудольность, диаметр                                                         |
| `directed`         | топологическая сортировка, обнаружение циклов, компоненты сильной связности                                        |
| `euler`            | критерий Эйлера и путь Хирхольцера                                                                                 |
| `genome_assembly`  | прочтения -> граф де Брёйна -> эйлеров путь -> собранный геном (линейный и кольцевой случаи)                       |
| `pointer_analysis` | унификационный анализ Стинсгарда на крошечной C-подобной программе с множествами points-to после каждого оператора |
| `visualize`        | один граф как DOT, SVG-картинка и автономная HTML-страница cytoscape.js во временной папке с печатью путей         |
| `random_graph`     | Эрдёш–Реньи $G(n, p)$: степени, лемма о рукопожатиях, компоненты, записанный DOT-файл                              |

`dijkstra` сталкивает два алгоритма кратчайших путей на одних и тех же вершинах.
`genome_assembly` и `pointer_analysis` применяют графы к данным и к анализу программ.
`visualize` создаёт файлы во временной папке и печатает их абсолютные пути.

## API

### Graph (`graph.rs`)

| Метод                                                       | Назначение                                        |
| ----------------------------------------------------------- | ------------------------------------------------- |
| `Graph::undirected()`, `Graph::directed()`                  | новый пустой граф                                 |
| `add_node(name)`                                            | добавить вершину, вернуть её id                   |
| `add_edge(u, v)`, `add_weighted_edge(u, v, w)`              | добавить ребро, вернуть его id                    |
| `add_edges(&[(u, v), ...])`                                 | добавить несколько рёбер единичного веса          |
| `node_count()`, `edge_count()`, `is_directed()`             | основные факты                                    |
| `node_name(u)`, `neighbors(u)`, `degree(u)`, `in_degree(u)` | прочитать структуру                               |
| `edge_weight(e)`, `adjacent(u, v)`                          | поиск рёбер                                       |
| `degrees()`                                                 | все степени (лемма о рукопожатиях, гистограммы)   |
| `Graph::erdos_renyi(n, p, seed)`                            | случайный граф $G(n, p)$, воспроизводимый по seed |

### Алгоритмы (`algo.rs`)

| Функция                                  | Результат                                                                |
| ---------------------------------------- | ------------------------------------------------------------------------ |
| `bfs(&g, start)`                         | порядок, расстояния, родители (дерево BFS)                               |
| `dfs(&g)`                                | времена входа/выхода `pre`/`post`, лес DFS, порядок завершения           |
| `connected_components(&g)`               | число и метки компонент (слабые для ориентированных)                     |
| `strongly_connected_components(&g)`      | Косараю, для ориентированных графов                                      |
| `is_cyclic(&g)`                          | обнаружение циклов (union-find или цвета DFS)                            |
| `topological_sort(&g)`                   | алгоритм Кана, `None` при цикле                                          |
| `dijkstra(&g, start)`                    | кратчайшие пути, неотрицательные веса                                    |
| `bellman_ford(&g, start)`                | кратчайшие пути с отрицательными рёбрами, `None` при отрицательном цикле |
| `min_spanning_tree(&g)`                  | алгоритм Краскала, возвращает id рёбер                                   |
| `prim(&g)`                               | алгоритм Прима с минимальной кучей, возвращает id рёбер                  |
| `find_eulerian_path(&g)`                 | эйлеров путь через Хирхольцера, `None`, если пути нет                    |
| `is_bipartite(&g)`                       | 2-раскраска, `None` при нечётном цикле                                   |
| `bridges(&g)`, `articulation_points(&g)` | алгоритм низких связей Тарьяна                                           |
| `greedy_coloring(&g)`                    | раскраска вершин жадным порядком                                         |
| `distance`, `eccentricity`, `diameter`   | меры расстояния без весов                                                |

Выбор алгоритма:

| У вас есть                                                        | Используйте                                                                                   |
| ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| невзвешенный граф, нужны расстояния или обход                     | `bfs`, `dfs`                                                                                  |
| взвешенный граф, неотрицательные веса                             | `dijkstra`                                                                                    |
| взвешенный граф с отрицательными рёбрами без отрицательных циклов | `bellman_ford`                                                                                |
| неориентированный граф, самое дешёвое остовное дерево             | `min_spanning_tree` (Краскал), `prim` (Прим)                                                  |
| каждое ребро посещается ровно один раз                            | `find_eulerian_path`                                                                          |
| ориентированный ациклический граф, нужен порядок                  | `topological_sort`                                                                            |
| компоненты                                                        | `connected_components` (неориентированный), `strongly_connected_components` (ориентированный) |
| мосты, точки сочленения или 2-раскраска                           | `bridges`, `articulation_points`, `is_bipartite`                                              |
| раскраска или меры расстояния                                     | `greedy_coloring`, `distance`, `eccentricity`, `diameter`                                     |

### Система непересекающихся множеств (`unionfind.rs`)

| Метод               | Назначение                                                           |
| ------------------- | -------------------------------------------------------------------- |
| `UnionFind::new(n)` | разбиение `0..n`, каждый элемент отдельно                            |
| `find(x)`           | представитель компоненты `x` (сжатие пути)                           |
| `union(a, b)`       | объединить две компоненты (по размеру), `false`, если уже объединены |
| `same(a, b)`        | связаны ли `a` и `b`                                                 |
| `push()`            | добавить новый элемент как отдельную компоненту                      |
| `classes()`         | классы эквивалентности текущего разбиения                            |

Работает за $O(n \alpha(n))$.
На нём построены алгоритм Краскала, обнаружение циклов в неориентированных графах и анализ указателей Стинсгарда.

### Матрица смежности (`matrix.rs`)

| Метод                             | Назначение                                   |
| --------------------------------- | -------------------------------------------- |
| `AdjMatrix::new(n, directed)`     | пустая матрица $n \times n$                  |
| `add_edge(u, v, w)`               | установить ребро (побеждает меньший вес)     |
| `has_edge(u, v)`, `weight(u, v)`  | проверки рёбер за $O(1)$                     |
| `neighbors(u)`, `in_neighbors(u)` | входящие и исходящие соседи                  |
| `from_graph(&g)`, `to_graph()`    | преобразование в `Graph` и обратно           |
| `count_walks(u, v, len)`          | число путей заданной длины (степень матрицы) |

### Графы де Брёйна (`de_bruijn.rs`)

Сборка генома из прочтений: вершины — (k-1)-меры, рёбра — k-меры, а эйлеров путь по графу записывает собранный геном.

| Метод                                | Назначение                                                           |
| ------------------------------------ | -------------------------------------------------------------------- |
| `DeBruijnGraph::build(&reads, k)`    | построить граф из прочтений (длинные прочтения нарезаются на k-меры) |
| `vertex_id(mer)`, `edge_label(u, v)` | найти (k-1)-мер вершины, k-мер ребра                                 |
| `eulerian_path()`                    | алгоритм Хирхольцера, `None`, если эйлерова пути нет                 |
| `genome_from_path(&path)`            | строка, записанная путём                                             |
| `assemble()`                         | путь и реконструкция в одном вызове                                  |

### Анализ указателей Стинсгарда (`steensgaard.rs`)

Анализ псевдонимов на основе унификации для крошечного C-подобного языка (`x = &y`, `x = y`, `x = *y`, `*x = y`).
Каждая переменная и ячейка — узел union-find не более чем с одним ребром points-to.
Ограничения разрешаются унификацией целей, что удерживает весь анализ на уровне $O(n \alpha(n))$.

| Элемент                                                      | Назначение                                        |
| ------------------------------------------------------------ | ------------------------------------------------- |
| `Stmt::AddrOf/Copy/Load/Store`                               | четыре формы операторов                           |
| `Steensgaard::new()`, `run(&program)`                        | проанализировать программу                        |
| `assign_addr`, `assign_copy`, `assign_deref`, `deref_assign` | по одному оператору за раз                        |
| `points_to(name)`, `points_to_sets()`                        | множества points-to (классы эквивалентности)      |
| `may_alias(x, y)`                                            | могут ли две переменные быть одной ячейкой памяти |

### Визуализация (`viz/`)

Крейт сам не строит макеты: размещение графа — трудная задача, и готовые инструменты справляются с ней хорошо.
Вместо этого крейт передаёт им текст.

| Бэкенд                        | Вывод                    | Размещает                                          |
| ----------------------------- | ------------------------ | -------------------------------------------------- |
| `viz::dot::render`            | исходник Graphviz DOT    | `dot`, `neato`, `fdp`, `circo`                     |
| `viz::cytoscape::render`      | JSON для cytoscape.js    | cytoscape.js (`cose`, `circle`, `concentric`, ...) |
| `viz::cytoscape::render_html` | автономная HTML-страница | cytoscape.js с CDN, без сервера                    |

DOT превращается в картинку любым движком Graphviz: `dot -O -Tsvg graph.dot` записывает `graph.dot.svg` рядом с исходником (флаг `-O` называет вывод по имени ввода).
JSON попадает прямо в cytoscape.js как опция `elements`.
`render_html` оборачивает тот же JSON в автономную страницу, которая открывается в браузере двойным щелчком.
JSON-бэкенд использует `serde`/`serde_json`, а HTML-обёртка — `indoc` (вместе единственные внешние зависимости крейта).
Схема узлов и рёбер — две структуры `#[derive(Serialize)]`, экранирование берёт на себя serde, поэтому любое имя вершины остаётся валидным JSON.
DOT нужен лишь небольшой специализированный экранировщик для собственных правил кавычек.

## Пути интеграции (web, wasm, js, desktop)

Два бэкенда покрывают лёгкие маршруты, а те же данные питают более сложные:

- **web**: подайте JSON в cytoscape.js для панорамирования, зума и щелчков, а исходник DOT отрисуйте на сервере с помощью graphviz.
- **wasm / js**: скомпилируйте крейт с помощью `wasm-pack`, предоставьте `Graph` и алгоритмы, отрисовывайте теми же бэкендами на стороне JS.
- **bevy / egui**: пропустите текстовые бэкенды и рисуйте `g.adj`/`g.edges` напрямую — модель состоит из обычных `Vec`, поэтому переносится в любой рендерер.
- **graphviz**: вывод `viz::dot` работает с `dot`, `neato`, `fdp`, `circo` и другими движками размещения.

## Тесты

`cargo test` запускает модульные тесты рядом с кодом в `src/` и док-тесты.
У каждого алгоритма есть случаи с явными ожидаемыми значениями: расстояния BFS на квадрате, сокращение Дейкстры через среднюю вершину, критерий Эйлера (цикл, путь или ничего), мосты и точки сочленения пути, враждебные имена вершин, остающиеся валидными JSON/DOT, конвейер де Брёйна (нарезка прочтений, повторные прочтения, петли, несбалансированные и несвязные графы), шаги унификации анализа указателей, круговые преобразования матрицы и подсчёты путей, классы эквивалентности union-find.
Док-тесты в `src/` заодно служат документацией.
