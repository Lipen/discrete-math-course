# graphs

Графы: моделирование, алгоритмы, визуализация.

Намеренно простая модель графа (без дженериков, без типажей --- только идентификаторы вершин `usize`, имена и взвешенные рёбра), классические алгоритмы и несколько способов отображения графа.

## Быстрый старт

```bash
cargo run -p graphs --example bfs_dfs
cargo run -p graphs --example visualize
cargo test -p graphs
```

## Модель

`Graph` хранит свои данные дважды, и оба представления открыты:

- `edges` --- список рёбер `(from, to, weight)`, который читают взвешенные алгоритмы (Дейкстра, Беллман–Форд, Краскал);
- `adj` --- списки смежности `adj[u] = [(neighbor, edge_id), ...]`, которые читают обходы (BFS, DFS).

Вершины --- это идентификаторы `usize` из `0..n` с необязательными строковыми именами. Рёбра ориентированы или неориентированы в зависимости от флага `directed` и могут повторяться (мультиграфы). Дублирование намеренно: оно отражает то, как псевдокод мыслит граф, и делает каждый алгоритм коротким.

Второе представление находится в `matrix.rs`: `AdjMatrix`, таблица весов рёбер размером `n x n`. Оно подходит для плотных графов, проверок рёбер за `O(1)` и матричных методов, таких как подсчёт путей через степени матрицы; предусмотрены преобразования в `Graph` и обратно (`AdjMatrix::from_graph`, `AdjMatrix::to_graph`). Матрица не может хранить параллельные рёбра, поэтому преобразование схлопывает их в самое лёгкое ребро.

![Взвешенный граф, размещённый graphviz (движок `dot`) из DOT-вывода крейта](assets/graphs-demo.svg)

Рисунок выше --- это граф демо `visualize`: крейт записывает исходный код DOT, а пример сам отображает картинку с помощью `dot -O -Tsvg` (движок `dot` размещает граф иерархически).

Исходник DOT для этого рисунка закоммичен в [`assets/graphs-demo.dot`](assets/graphs-demo.dot) --- можно перестроить разметку любым движком Graphviz (`dot`, `neato`, `fdp`, `circo`).

## API

### Graph (`graph.rs`)

| Метод | Назначение |
| --- | --- |
| `Graph::undirected()`, `Graph::directed()` | Новый пустой граф |
| `add_node(name)` | Добавить вершину, вернуть её id |
| `add_edge(u, v)`, `add_weighted_edge(u, v, w)` | Добавить ребро, вернуть его id |
| `add_edges(&[(u, v), ...])` | Добавить несколько рёбер единичного веса |
| `node_count()`, `edge_count()`, `is_directed()` | Основные факты |
| `node_name(u)`, `neighbors(u)`, `degree(u)`, `in_degree(u)` | Прочитать структуру |
| `edge_weight(e)`, `adjacent(u, v)` | Поиск рёбер |
| `degrees()` | Все степени (лемма о рукопожатиях, гистограммы) |
| `Graph::erdos_renyi(n, p, seed)` | Случайный граф $G(n, p)$, воспроизводимый |

### Алгоритмы (`algo.rs`)

| Функция | Результат |
| --- | --- |
| `bfs(&g, start)` | Порядок, расстояния, родители (дерево BFS) |
| `dfs(&g)` | Времена входа/выхода `pre`/`post`, лес DFS, порядок завершения |
| `connected_components(&g)` | Число и метки компонент (слабые для ориентированных) |
| `strongly_connected_components(&g)` | Косараю, для ориентированных графов |
| `is_cyclic(&g)` | Обнаружение циклов (union-find / цвета DFS) |
| `topological_sort(&g)` | Алгоритм Кана, `None` при цикле |
| `dijkstra(&g, start)` | Кратчайшие пути, неотрицательные веса |
| `bellman_ford(&g, start)` | Кратчайшие пути с отрицательными рёбрами, `None` при отрицательном цикле |
| `min_spanning_tree(&g)` | Алгоритм Краскала, возвращает id рёбер |
| `prim(&g)` | Алгоритм Прима, минимальная куча, возвращает id рёбер |
| `find_eulerian_path(&g)` | Эйлеров путь через Хирхольцера, `None`, если не существует |
| `is_bipartite(&g)` | 2-раскраска, `None` при нечётном цикле |
| `bridges(&g)`, `articulation_points(&g)` | Алгоритм низких связей Тарьяна |
| `greedy_coloring(&g)` | Раскраска вершин, жадный порядок |
| `distance`, `eccentricity`, `diameter` | Меры расстояния без весов |

Выбор алгоритма:

| У вас есть | Используйте |
| --- | --- |
| невзвешенный граф, нужны расстояния или обход | `bfs`, `dfs` |
| взвешенный граф, неотрицательные веса | `dijkstra` |
| взвешенный граф с отрицательными рёбрами (без отрицательных циклов) | `bellman_ford` |
| неориентированный граф, самое дешёвое остовное дерево | `min_spanning_tree` (Краскал), `prim` (Прим) |
| нужно посетить каждое ребро ровно один раз | `find_eulerian_path` |
| ориентированный ациклический граф, нужен порядок | `topological_sort` |
| нужны компоненты | `connected_components` (неориентированный), `strongly_connected_components` (ориентированный) |
| нужны мосты, точки сочленения или 2-раскраска | `bridges`, `articulation_points`, `is_bipartite` |
| нужны цвета или меры расстояния | `greedy_coloring`, `distance`, `eccentricity`, `diameter` |

### Система непересекающихся множеств (`unionfind.rs`)

| Метод | Назначение |
| --- | --- |
| `UnionFind::new(n)` | Разбиение `0..n`, каждый элемент отдельно |
| `find(x)` | Представитель компоненты `x` (сжатие пути) |
| `union(a, b)` | Объединить две компоненты (объединение по размеру); `false`, если уже объединены |
| `same(a, b)` | Связаны ли `a` и `b`? |
| `push()` | Добавить новый элемент как собственную компоненту |
| `classes()` | Классы эквивалентности текущего разбиения |

Работает за $O(n \alpha(n))$; используется алгоритмом Краскала, обнаружением циклов в неориентированных графах и анализом указателей Стинсгарда.

### Матрица смежности (`matrix.rs`)

| Метод | Назначение |
| --- | --- |
| `AdjMatrix::new(n, directed)` | Пустая матрица `n x n` |
| `add_edge(u, v, w)` | Установить ребро (побеждает меньший вес) |
| `has_edge(u, v)`, `weight(u, v)` | Проверки рёбер за $O(1)$ |
| `neighbors(u)`, `in_neighbors(u)` | Входящие и исходящие соседи |
| `from_graph(&g)`, `to_graph()` | Преобразование в `Graph` и обратно |
| `count_walks(u, v, len)` | Число путей заданной длины (степень матрицы) |

### Графы де Брёйна (`de_bruijn.rs`)

Сборка генома из прочтений: вершины --- это (k-1)-меры, рёбра --- k-меры, а эйлеров путь по графу записывает собранный геном.

| Метод | Назначение |
| --- | --- |
| `DeBruijnGraph::build(&reads, k)` | Построить граф из прочтений (длинные прочтения нарезаются на k-меры) |
| `vertex_id(mer)`, `edge_label(u, v)` | Найти (k-1)-мер вершины, k-мер ребра |
| `eulerian_path()` | Алгоритм Хирхольцера; `None`, если эйлерова пути не существует |
| `genome_from_path(&path)` | Строка, записанная путём |
| `assemble()` | Путь + реконструкция в одном вызове |

### Анализ указателей Стинсгарда (`steensgaard.rs`)

Анализ псевдонимов на основе унификации для крошечного C-подобного языка (`x = &y`, `x = y`, `x = *y`, `*x = y`). Каждая переменная и ячейка --- это узел union-find с не более чем одним ребром points-to; ограничения разрешаются унификацией целей, что и удерживает весь анализ на уровне $O(n \alpha(n))$.

| Элемент | Назначение |
| --- | --- |
| `Stmt::AddrOf/Copy/Load/Store` | Четыре формы операторов |
| `Steensgaard::new()`, `run(&program)` | Проанализировать программу |
| `assign_addr`, `assign_copy`, `assign_deref`, `deref_assign` | По одному оператору за раз |
| `points_to(name)`, `points_to_sets()` | Множества points-to (классы эквивалентности) |
| `may_alias(x, y)` | Могут ли две переменные быть одной и той же ячейкой памяти? |

### Визуализация (`viz/`)

Крейт сам не строит макеты: размещение графа --- сложная задача, и готовые инструменты хорошо с ней справляются. Вместо этого крейт передаёт им текст:

| Бэкенд | Вывод | Размещается |
| --- | --- | --- |
| `viz::dot::render` | Исходный код Graphviz DOT | `dot`, `neato`, `fdp`, `circo` |
| `viz::cytoscape::render` | JSON для cytoscape.js | cytoscape.js (`cose`, `circle`, `concentric`, ...) |
| `viz::cytoscape::render_html` | автономная HTML-страница | cytoscape.js с CDN, без сервера |

DOT превращается в картинку любым движком Graphviz: `dot -O -Tsvg graph.dot` записывает `graph.dot.svg` рядом с исходником (флаг `-O` называет вывод по имени ввода). JSON попадает прямо в cytoscape.js как опция `elements`; `render_html` оборачивает тот же JSON в автономную страницу, которая открывается в браузере двойным щелчком. JSON-бэкенд использует `serde`/`serde_json`, а HTML-обёртка использует `indoc` (вместе --- единственные внешние зависимости крейта): схема узлов/рёбер --- это две структуры `#[derive(Serialize)]`, и serde берёт на себя экранирование, так что любое имя вершины остаётся валидным JSON. DOT нужен лишь небольшой специализированный экранировщик для собственных правил кавычек.

## Демо

| Демо | Показывает |
| --- | --- |
| `bfs_dfs` | Слои и расстояния BFS; времена входа/выхода DFS на сквозном примере графа |
| `dijkstra` | Дейкстра против Беллман–Форд, отрицательные рёбра, отрицательные циклы, восстановление пути |
| `mst` | Минимальное остовное дерево Краскала на взвешенном графе |
| `structure` | Компоненты, мосты, точки сочленения, двудольность, диаметр |
| `directed` | Топологическая сортировка, обнаружение циклов, компоненты сильной связности |
| `euler` | Критерий Эйлера и путь Хирхольцера |
| `genome_assembly` | Прочтения -> граф де Брёйна -> эйлеров путь -> собранный геном (линейный и кольцевой случаи) |
| `pointer_analysis` | Анализ на основе унификации Стинсгарда на крошечной C-подобной программе, с множествами points-to после каждого оператора |
| `visualize` | Один граф, записанный как DOT, SVG-картинка (отрисованная с помощью `dot -O -Tsvg`) и автономная HTML-страница cytoscape.js во временной папке; печатает пути |
| `random_graph` | Эрдёш–Реньи $G(n, p)$: степени, лемма о рукопожатиях, компоненты; записывает DOT-файл |

## Пути интеграции (web, wasm, js, desktop)

Два бэкенда покрывают лёгкие маршруты; те же данные питают более сложные:

- **web**: подайте JSON в cytoscape.js для панорамирования/зума/щелчка; исходный DOT отрисовывается на сервере с помощью graphviz;
- **wasm / js**: скомпилируйте крейт с помощью `wasm-pack`, предоставьте `Graph` + алгоритмы и отрисуйте теми же бэкендами на стороне JS;
- **bevy / egui**: пропустите текстовые бэкенды и рисуйте `g.adj`/`g.edges` напрямую --- модель --- это просто `Vec`, так что она переносится в любой рендерер;
- **graphviz**: вывод `viz::dot` работает с `dot`, `neato`, `fdp`, `circo` и другими движками размещения.

## Тесты

```bash
cargo test -p graphs
```

У каждого алгоритма рядом с кодом в `src/` есть проверенные вручную случаи: расстояния BFS на квадрате, сокращение Дейкстры через среднюю вершину, критерий Эйлера (цикл против пути против отсутствия), мосты/точки сочленения пути, враждебные имена вершин, остающиеся валидными JSON/DOT, конвейер де Брёйна (нарезка прочтений, повторные прочтения, петли, несбалансированные и несвязные графы), шаги унификации анализа указателей, круговые обходы матрицы и подсчёты путей, а также классы эквивалентности union-find. Док-тесты в `src/` служат также документацией: `cargo test -p graphs` запускает их все.
